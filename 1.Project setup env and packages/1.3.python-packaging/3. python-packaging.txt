Convert requirements.txt to pyproject.toml

1. Current requirements.txt:
    flask==2.3.2
    requests>=2.31.0
    numpy
    pytest
    black

2. same pyproject.toml
    [project]
    name = "my-app"
    version = "1.0.0"
    description = "My backend service"
    dependencies = [
        "flask==2.3.2",
        "requests>=2.31.0",
        "numpy"
    ]

    [project.optional-dependencies]
    dev = [
        "pytest",
        "black"
    ]

3. Install dependencies
    pip install .
    pip install .[dev]

 - Use both like:
    pyproject.toml        👈 source of truth
    requirements.txt      👈 generated for deployment

    generate like:
    pip freeze > requirements.txt

Setup project using poetry:

1. install poetry
pipx install poetry
    // pip -> when you want to Install libraries for project development.
    // pipx -> Install standalone CLI tools for system-wide use. regardless of project like Black, Poetry.

2. initialize your project
for new project
    poetry new my-project

for existing project
    cd my-folder
    poetry init
        - then interaction tool

3. Manage dependencies
Instead of editing the file manually, use Poetry's commands to install dependencies
    poetry add requests
        - This updates your pyproject.toml and creates a poetry.lock file to pin exact versions
        - Poetry usually stores compatible version ranges using the ^ operator by default.
        - for specific use - poetry add requests==2.12.1

    poetry install
        - Creates/uses a virtual environment and installs dependencies from pyproject.toml and poetry.lock.

4. Run and build
    Run project
    poetry run python main.py 

    build project
    poetry build

5. if you want to bump project version
    poetry version minor
        0.2.0 -> 0.3.0

6. Poetry created this files:
    pyproject.toml
    → Project metadata + dependency definitions

    poetry.lock
    → Exact resolved dependency versions for reproducible installs

Migrate the project from requirements.txt to poetry

1. initialize project
cd your-project
poetry init
    - interaction promts for project name and version

2. add dependencies from requirements.txt
poetry add $(cat requirements.txt)
    - reads the file and runs poetry add for each library, which resolves versions and creates the poetry.lock file automatically.

3.Handle Development Dependencies
poetry add --group dev $(cat requirements-dev.txt)
    - If you have a separate file for dev tools (like pytest or black), 
    add them to a specific "group" so they aren't included in your production build.

4. Verify and Cleanup
poetry show --tree      # See your new dependency tree
rm requirements.txt     # Safely remove the old file

uv vs poetry:
    - Using both together can create conflicts/confusion. 
        because both tools try to manage:
         dependencies
         lock files
         virtual environments
         package workflows
    
    Poetry = opinionated project manager
        Controls:
            dependency lifecycle
            packaging workflow
            lock management

    uv = toolkit/unified fast tooling
        Can act as:
            pip replacement
            venv replacement
            resolver
            project manager
            Poetry-like dependency management

Setup project using uv

1. Initialize Project
for New project
    uv init my-project
        This creates:
         - pyproject.toml
         - starter project structure

for Existing project
    cd my-project
    uv init

2. Manage Dependencies
Add dependency
    uv add requests
    This:
     - updates pyproject.toml
     - creates uv.lock
        - reproducible dependency versions
        - consistent installs across team/CI
     - installs dependency
     - uv add "requests==2.32.0" for adding specific version    

Add Install/sync dependencies
    uv sync
    This:
     - that synchronizes a Python project's virtual environment (.venv) with its uv.lock file and pyproject.toml
     - creates virtual environment if needed
     - installs exact locked versions

Remove dependency
    uv remove requests

3. Virtual Environment Management
Create environment
    uv venv
    Usually creates:
        .venv/
        source .venv/bin/activate => Activate environment

4. Run Project
Run directly by running
    uv run python main.py
    Advantage:
        - automatically uses project environment or create virtual env if not presented.

5. Build Project
    uv build
     - Creates distributable package files.
