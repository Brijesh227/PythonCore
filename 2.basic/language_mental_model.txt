-----------------------------
Compiled language → Source code is translated into machine code before running.
Interpreted language → Code is read and executed step-by-step by another program at runtime.

But Modern Languages Are Hybrid

    Modern languages mix:
     - Compilation
     - Interpretation
     - Virtual machines
     - JIT (Just-In-Time compilation)

| Language   | Main Execution Style   | Runtime Layer | Machine Code Generation |
| ---------- | ---------------------- | ------------- | ----------------------- |
| C++        | Ahead-of-time compiled | Minimal       | Before execution        |code → CPU (Minimal abstraction.)
| Python     | Bytecode + VM          | Heavy runtime | Rare/minimal            |code → Python VM → CPU (Maximum developer productivity.)
| Java       | Bytecode + JVM + JIT   | JVM           | During runtime          |code → JVM → optimized native code → CPU (Portable enterprise runtime.)
| JavaScript | Interpreted + JIT      | JS Engine     | During runtime          |code → adaptive JIT engine → optimized machine code (Dynamic runtime optimization.)

------------------------------
 - Core Mental Model

    Think about computers like this:
        Code  →  Translator  →  CPU Machine Instructions  →  Computer Runs

    - The difference is mainly:
       WHEN translation happens
       WHAT code gets generated
       WHO executes it

1. C,C++ 
    Compiled Languages 
    main.cpp
       ↓
    Compiler (g++, clang)
       ↓
    Machine code (.exe / binary)
       ↓
    CPU runs directly

    Advantages
     - Very fast execution
     - Optimized heavily
     - Direct hardware control
     - Low memory overhead

    Disadvantages
    - Compilation step needed
    - Platform dependent
        Windows binary ≠ Linux binary
    - Development slower sometimes

2. Python: 
    - Interpreted Languages (Traditional Python, shell scripts)
    - The interpreter itself is already a compiled program.

    .py file
       ↓
    Parser
       ↓
    AST
       ↓
    Compiler
       ↓
    Bytecode (.pyc)
       ↓
    PVM evaluation loop (continous loop)
       ↓
    Machine instructions
       ↓
    CPU

    Advantages
     - Easy development
     - Portable
     - Interactive REPL
     - Dynamic

    Disadvantages
     - Slower
     - More runtime overhead
     - More memory usage

    Python Mental Model: 
        - Python code runs inside a big Python application.
        - Your code does NOT run directly on CPU.
        - Every value is a Python object. (x = 5)

        Python Code
           ↓
        Bytecode Compilation (cpython compiler)
           ↓
        Python Bytecode (.pyc)
           ↓
        Python Virtual Machine (PVM)
           ↓
        Machine Instructions

    What is Bytecode in Python:
        - low level code not machine code
        - Bytecode Compiler: e.x., cpython compiler(standard implementation), jython(java binaries), Iron python, stack less(concurrency), PyPy(performance)
        - When CPython starts running a .py file, first, it performs a compilation step:
            x = 5
            print(x)

         gets transformed into an internal representation and then into Python bytecode.
            import dis

            def f():
                x = 5
                print(x)

            dis.dis(f)

            LOAD_CONST 5
            STORE_FAST x
            LOAD_GLOBAL print
            LOAD_FAST x
            CALL
            RETURN_VALUE

        compiles x = 5+10 into Bytecode
            LOAD_CONST 5
            LOAD_CONST 10
            ADD
            STORE_NAME x
        Then Python VM executes it.

    PVM:
        - run time engine
        - also known as python interpreter
        - continous loop running for bytecode or normal python script

3. Java: Java introduced the major VM revolution.
    - Java runs inside an operating system built specifically for Java.
    - Java compiles to platform-independent bytecode NOT directly to machine code. Then JVM handles the rest.

    Java Source (.java)
       ↓
    javac Compiler
       ↓
    Bytecode (.class)
       ↓
    JVM (Java Virtual Machine)
       ↓
    JIT Compilation
       ↓
    Machine Code

    JVM handles:
        - memory
        - garbage collection
        - threading
        - optimization
        - security

    Why Java Is Faster Than Python
        Because JVM uses:
         - JIT compiler
         - runtime optimization

        what is JIT (Just-In-Time Compilation)

        Initially:
            Bytecode → interpreted

        But JVM notices:

            "This function runs 1 million times."

        Then converts it into optimized machine code.
        This is why Java becomes very fast after warm-up.

Javascript:
    JavaScript evolved the most dramatically.    
     - Originally: simple interpreted scripting language
     - Now: highly optimized JIT language

    JavaScript(V8)

     JavaScript Source
         ↓
       Parser
         ↓
        AST
         ↓
      Bytecode
         ↓
      Interpreter
         ↓
      JIT Compiler
         ↓
      Optimized Machine Code

    - JavaScript is a highly adaptive runtime engine.
    - Modern JS engines:
        watch your code
        profile behavior
        optimize hot paths dynamically
    - function add(a, b) {
        return a + b;
      } => add("a", "b")

-----------------------------------------

People often say:

    Compiled = fast
    Interpreted = slow

Not always true.

Modern JIT languages can outperform poorly optimized compiled code.

Real performance depends on:
    runtime optimizations
    memory access
    algorithms
    cache locality
    data structures
